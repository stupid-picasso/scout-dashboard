# Pokémon GO Progress Tracker – Complete Project Handoff

## Project Overview
A Progressive Web App (PWA) for Pokémon GO players to track their collection, calculate IV/PvP rankings, and bulk-import Pokémon data from screenshots or screen recordings using OCR and automated video frame extraction.

---

## Architecture & Tech Stack

### Frontend
- **Framework:** Vanilla JS + React-like pattern (Design Components, `.dc.html` format)
- **PWA:** Service worker (`sw.js`), manifest (`manifest.json`), installable on iOS/Android
- **Storage:** localStorage (persists collection, player data, import history)
- **iOS frame:** Custom frame component for iPhone mockup display

### Backend / Data Processing
- **Video extraction:** FFmpeg (frame dumping at configurable fps)
- **OCR:** Tesseract (pytesseract wrapper on Windows; GitHub Actions uses `tesseract-ocr` package on Ubuntu)
- **CSV parsing:** Python regex-based field extraction (61-column schema)
- **CI/CD:** GitHub Actions workflow (`.github/workflows/extract.yml`)

### Data Format
- **Input:** MP4/MOV screen recordings (native iOS 5 fps recommended; compressed to 5fps acceptable)
- **Intermediate:** PNG frames extracted at user-specified fps (default 6)
- **Output:** CSV (no header row; columns: pokemon_name, dex_number, cp, hp, level, attack_iv, defense_iv, stamina_iv, iv_percent, gender, height, weight, size_class, type_1, type_2, weather_boosted, favorite, shiny, shadow, purified, lucky, costume, event, background, dynamax, gigantamax, mega_capable, buddy_level, current_buddy, caught_date, caught_location, trainer_notes, tag_list, appraisal_team, appraisal_attack_bar, appraisal_defense_bar, appraisal_hp_bar, fast_move, charged_move_1, charged_move_2, fast_move_type, charged_move_type_1, charged_move_type_2, stardust_powerup_cost, candy_powerup_cost, xl_candy_powerup_cost, stardust_evolution_cost, evolution_candy_cost, current_candy, current_xl_candy, mega_energy, is_tradeable, is_legendary, is_mythical, is_ultra_beast, is_event, is_costume, is_favorite, has_second_move, is_best_buddy, pokeball_type, catch_method, friendship_history, notes)

## Core Workflows

### 1. Video → CSV (Automated via GitHub Actions)

**Trigger:** Push MP4/MOV to `videos/` folder on GitHub

**Workflow steps (`.github/workflows/extract.yml`):**
1. Check out repo
2. Install Python 3.11 + dependencies: `pytesseract`, `pillow`, `ffmpeg`, `tesseract-ocr`
3. Run `pogo_extract.py --video videos/*.mp4 --out data/pokemon.csv --fps 6`
   - ffmpeg dumps frames: `ffmpeg -i input.mp4 -vf fps=6 frames_tmp/frame_%06d.png`
   - Tesseract OCR each frame (no preprocessing, full image)
   - Regex parse text output into 61-column schema
   - Write CSV to `data/pokemon.csv`
4. Commit CSV back to repo (auto-commit if changes)

**Local testing (Windows/Mac):**
```bash
pip install pytesseract pillow
# Install Tesseract exe (Windows: https://github.com/UB-Mannheim/tesseract/wiki)
# Add to PATH: C:\Program Files\Tesseract-OCR\tesseract.exe
python pogo_extract.py --video "ScreenRecording_07-29-2026 12-55-42_1-compressed.MP4" \
  --out pokemon.csv --fps 6
```

### 2. Upload CSV → Scout Dashboard

**User flow (in-app):**
1. User clicks "IMPORT CSV" in Scout Dashboard
2. File picker opens; selects `pokemon.csv` from downloads
3. CSV parsed row-by-row; each Pokémon added to roster (localStorage)
4. UI updates with new team member

**Data validation:**
- Skip blank rows
- Name lookup via `pokemon-data.js` (dex matching)
- CP → level estimation (binary search against stat product)
- IV % calculation: (atk_iv + def_iv + sta_iv) / 45 * 100
- PvP rank: simulate battles against meta (Great/Ultra/Master leagues)

### 3. Roster Display & Interaction

**Scout Dashboard features:**
- **List view:** Show all Pokémon, sortable by CP, IV%, PvP rank
- **Filters:** Type, IV range, legendary/mythical, favorited, tagged
- **Detail card:** Name, CP, moves, IVs, candy, XL candy, powerup cost, PvP rank
- **Quick actions:** Mark favorite, rename, delete, plan powerup

**Persistence:** All edits saved to localStorage immediately

## IV/PvP Calculation Details

### IV Percentage
```
iv_percent = (attack_iv + defense_iv + stamina_iv) / 45 * 100
```
Range: 0–100%

### CP Formula
```
CP = (attack + attack_iv) × (defense + defense_iv)^0.5 × (stamina + stamina_iv)^0.5 × power^2 / 10
power = 0.5 * (1.0 + level_adjusted_cpm)
```
`level_adjusted_cpm` is a lookup table; level inferred from CP via binary search.

### PvP Rank (Great/Ultra/Master League)
1. Filter meta Pokémon by league CP cap (1500/2500/no-cap)
2. For target Pokémon: simulate battle win-rate vs. meta
3. Rank by win-rate (stat product as tiebreaker)
4. Return rank %ile and absolute rank #

## Regex Parsing Rules (`pogo_extract.py`)

**Field extraction from OCR text:**

| Field | Regex Pattern | Notes |
|-------|---------------|-------|
| `pokemon_name` | `^[A-Z][A-Za-z\s]+$` (first capitalized line) | Detects swipe boundary |
| `cp` | `\bCP\s*(\d+)` | "CP 3139" |
| `hp` | `\bHP\s*(\d+)` | "HP 114" |
| `attack_iv` | `Atk\s*(\d+)` | "Atk 15" |
| `defense_iv` | `Def\s*(\d+)` | "Def 12" |
| `stamina_iv` | `Sta\s*(\d+)` | "Sta 13" |
| `type_1` | `(Normal\|Fire\|Water\|...) JAB` | First type before move name |
| `fast_move` | `JAB\|SCRATCH\|...` | Common fast move names |
| `charged_move_1` | `BOMB\|BEAM\|PUNCH\|...` (after fast move) | Charged move name |
| `current_candy` | `(\d+)\s*Candy` | "42 Candy" |
| `current_xl_candy` | `\b(\d+)\s*XL\s*Candy` | "5 XL Candy" |
| `stardust_powerup_cost` | `(\d+)\s*Stardust` | Star cost for next power-up |

**Known weaknesses (flagged for tuning):**
- `current_xl_candy` regex `\bS(1)\b` is placeholder; needs real OCR output sample to refine
- `costume` field always blank (visual-only; needs image classification, out of scope)
- `catch_method` regex assumes "CAUGHT X Y" phrasing; multi-line cases ("CAUGHT AFTER DEFEATING LEADER ARLO") untested
- `guess_name()` function detects Pokémon name by capitalization + Dex lookup; may false-positive on OCR noise (e.g., random capitals in background text)

## GitHub Workflow Details (`.github/workflows/extract.yml`)

**Trigger:**
```yaml
on:
  push:
    paths:
      - 'videos/*.mp4'
      - 'videos/*.mov'
```
Runs only when `.mp4` or `.mov` file is added/modified in `videos/` folder.

**Steps:**
1. `actions/checkout@v4` — clone repo
2. `actions/setup-python@v4` (Python 3.11)
3. Install deps:
   - `pip install pytesseract pillow`
   - `apt-get install tesseract-ocr ffmpeg` (Ubuntu runner)
4. Run script: `python pogo_extract.py --video videos/*.mp4 --out data/pokemon.csv --fps 6 --keep-frames`
5. Auto-commit: `git config` + `git add data/pokemon.csv` + `git commit -m "Extract Pokémon data from video"`
6. Push: `git push`

**Output:**
- CSV written to `data/pokemon.csv` (61 columns, no header)
- Frames stay in `frames_tmp/` (deleted after unless `--keep-frames` passed)
- Workflow log visible under repo **Actions** tab

## Engineering notes (current, v53.125)

The sections above describe the original video/OCR pipeline. The app has since grown; this is what a new session needs.

- **Source of truth:** `Scout Dashboard.dc.html` and `pokemon-mechanics.js`. `index.html`, `Scout Dashboard.html` and `Scout Dashboard Standalone.dc.html` are generated by `scripts/propagate_edits.py` (`snapshot` before editing, `apply` once after, `verify` any time). Never run `apply` twice without a `snapshot`. The `propagate.yml` workflow does the same on push.
- **Tests:** `node scripts/test_ranking.js`, `node scripts/test_roster_logic.js` (pull real methods out of the source and run them), and `node scripts/smoke_render.js` (real Chromium: roster rows, swipe, long-press, detail sheet, every tab, planners, no raw `\u` escapes). CI runs all three (`.github/workflows/test.yml`).
- **Data imports (generated blocks in `pokemon-mechanics.js`):** `import_pvp_tier_data.py` (PvPoke tiers, recommended movesets, matchups) and `import_pvpoke_gamemaster.py` (species typing, buddy distance, second-move cost, PvP fast-move numbers, league meta). `update-pvpoke-data.yml` re-runs both weekly and opens a PR.
- **Ranking model:** PvP = IV stat-product rank + PvPoke species tier + recommended moves; "PvP ready" needs measured IVs, 90%+ rank and an S/A/B species. Raids = DPS x (HP x DEF)^0.4 on real move data, with best-legal-moveset potential, weather and boss-damage survivability in Raid Counters. PvP max level (40/50/51) is a setting that re-ranks the roster.
- **Credentials** (Gemini keys, API endpoint, GitHub token) live in this browser's localStorage only and are never written to Firestore or backup snapshots.
- **Gotchas that cost real time:**
  - A template value that resolves to `undefined` makes React omit the attribute (`data-swipe-row="{{ p.idx }}"` needed `idx` on the row view-model).
  - `animation-fill-mode: both` keeps a finished keyframe's `transform` on top of inline styles and leaves a composited layer that Safari renders soft. Use `backwards`.
  - `\uXXXX` only works in JS strings; in template text use HTML entities.
  - The bundles are a different dialect (`sc-camel-on-click`, JSON-escaped); large markup edits that `apply` cannot place must be spliced in by hand and checked for div balance.

## Engineering notes (v53.135+): QA suite, iOS layer, data sources

- **QA:** `scripts/qa/` holds a deterministic fixture (`make_fixture.js`), a data audit against the game master and PvPoke (`qa_accuracy.js`), ~170 end-to-end cases in Chromium (`qa_run.js`, suites a/b/c), and `make_report.py` which writes `docs/QA_REPORT.md`. - **Propagate discipline:** `apply` diffs `.propagate_baseline/dc.html` against the current source. The baseline MUST equal what the bundles contain. If you `snapshot` before an earlier edit was applied, bundles silently miss it. When in doubt: `git checkout HEAD -- index.html "Scout Dashboard.html" "Scout Dashboard Standalone.dc.html" sw.js` then `apply`. `apply` also re-embeds `pokemon-mechanics.js` into both bundles every time (it used to skip when the embedded copy had drifted).

- **Game-master data (single download, `scripts/import_mega_levels.py`):** Mega Level rules and Mega forms (`MEGA_LEVEL_DATA`) and base-form species rows (`SPECIES_GM`, applied over `BASE_STATS`). Evolution and movepool importers now key regional forms as `name|form`.
- **Events/GBL:** `scripts/update_events_gbl.py` (every 6 h, `.github/workflows/update-events-gbl.yml`) writes `data/feed.json` with the weekly cups, their real rules from the game master (`COMBAT_LEAGUE_*`) and the PvPoke ranking each maps to. `verify_feed_official.py` cross-checks it against the pokemongo.com season page.
- **iOS design layer:** the last block of the `<style>` in the dc file. Tokens (`--ios-*`), SF font stack, grouped surfaces and filled controls are CSS; attribute selectors must match the *serialised* inline style (`prop: value;`). The tab bar is five items plus a More sheet. Roster rows are the grouped-list design; manual IV entry is behind "Enter IVs".

## Gemini video import pipeline (parallel, tiered)
- `gemini_pool.py`: lanes per (model, key), per-lane RPM, dead-lane handling, bulk/verify tiers, `suspicion()`.
- Model names are discovered, not hardcoded: `choose_models()` takes the newest stable `gemini-<ver>-flash-lite` (bulk, max 3) and `-flash` (verify, max 5) from ListModels; previews/tts/image/live are skipped. Built-in names are only a fallback if ListModels fails. Override with env `GEMINI_BULK_MODELS` / `GEMINI_VERIFY_MODELS` (comma lists). Retired models vanish from ListModels or 404 and their lanes are dropped; unread batches fall to the verify tier. Every run (extract, IV import, preflight) first calls `active_models()`: ListModels, then a free `countTokens` check per model; a model answering 404/403 on every key (Google keeps listing retired models) is left out of the cycle, up to 6 per tier, newest first. The log prints the active and dropped models. Overload spill: when every bulk lane's last call failed (or 40%+ of its calls did) and none is ready, `Pool.acquire(..., spill=True)` lends idle verify-tier lanes to bulk work (max `SPILL_CAP`=14 calls per lane, the free tier allows 20 a day).
- Thinking is minimal (ladder in `call_gemini`). HDR tone-map downscales inside the first zscale.
- Tests: `scripts/test_gemini_pool.py`, `scripts/test_extract_pipeline.py` (run in Tests workflow).
- Accuracy per model: run the "Benchmark Gemini Models" workflow; output `data/benchmark_models.md`.


## Size classes, showcase protection and motion (added with the "do all 7" pass)
- `scripts/import_size_data.py` writes the `SIZE_DATA` block in `pokemon-mechanics.js` from the game master (per species and form: Pokedex height, weight and the six size cut-offs; the refresh runs in `update-pvpoke-data.yml`). `sizeInfoFor(dex, form, heightM)` returns `{cls: XXS|XS|M|XL|XXL, ratio, valid, borderline}`. The cut-offs are read as heights in metres from their values (they match the Pokedex height times 0.49/0.5/0.75/1.25/1.5/1.75 for most species); the game does not document them and they are NOT yet confirmed against in-game screenshots.
- App: `sizeOf / sizeTagOf / sizeProtected`. XXL and XXS (optionally XL/XS, setting `protectSizes` under Home > Setup) are never offered as transfer suggestions (verdict, triage queue, dominated duplicates, transfer-safe pools) and are KEEP with a showcase reason. A height outside what the species can have (`valid:false`) neither tags nor protects. Roster filters XXL/XXS and XL/XS, search builder terms, rename token `{size}`, and Tools > Showcase list.
- Bulk tab icon shows the number of Pokemon waiting for a form or type (`bulkBadge`). Roster has filters "Form to check" and "No type". A roster pill "Last import: N changed" opens a sheet with per-Pokemon Undo (`lastImport`, `revertImportRow`).
- Motion: number roll-ups via `data-countup` (MutationObserver in `installCountUp`), Bulk row close (`bulkAnimateOut`, commit delayed 340 ms), import row flash (`data-changed`), press-scale on buttons, spring overshoot in `sheetUp`. All skip under Reduce Motion where they animate.
- A readability floor (12px minimum) is applied by one CSS rule over inline font sizes; the design detector's 176 low-contrast flags are false alarms against the dark theme (axe color-contrast finds none on the real render).
