# Pokémon GO Progress Tracker – Complete Project Handoff

## Project Overview
A Progressive Web App (PWA) for Pokémon GO players to track their collection, calculate IV/PvP rankings, and bulk-import Pokémon data from screenshots or screen recordings using OCR and automated video frame extraction.

---

## Architecture & Tech Stack

### Frontend
- **Framework:** Vanilla JS + React-like pattern (Design Components, `.dc.html` format)
- **PWA:** Service worker (`sw.js`), manifest (`manifest.json`), installable on iOS/Android
- **Storage:** localStorage (persists collection, player data, import history)
- **iOS frame:** Custom frame component for iPhone mockup display

### Backend / Data Processing
- **Video extraction:** FFmpeg (frame dumping at configurable fps)
- **OCR:** Tesseract (pytesseract wrapper on Windows; GitHub Actions uses `tesseract-ocr` package on Ubuntu)
- **CSV parsing:** Python regex-based field extraction (61-column schema)
- **CI/CD:** GitHub Actions workflow (`.github/workflows/extract.yml`)

### Data Format
- **Input:** MP4/MOV screen recordings (native iOS 5 fps recommended; compressed to 5fps acceptable)
- **Intermediate:** PNG frames extracted at user-specified fps (default 6)
- **Output:** CSV (no header row; columns: pokemon_name, dex_number, cp, hp, level, attack_iv, defense_iv, stamina_iv, iv_percent, gender, height, weight, size_class, type_1, type_2, weather_boosted, favorite, shiny, shadow, purified, lucky, costume, event, background, dynamax, gigantamax, mega_capable, buddy_level, current_buddy, caught_date, caught_location, trainer_notes, tag_list, appraisal_team, appraisal_attack_bar, appraisal_defense_bar, appraisal_hp_bar, fast_move, charged_move_1, charged_move_2, fast_move_type, charged_move_type_1, charged_move_type_2, stardust_powerup_cost, candy_powerup_cost, xl_candy_powerup_cost, stardust_evolution_cost, evolution_candy_cost, current_candy, current_xl_candy, mega_energy, is_tradeable, is_legendary, is_mythical, is_ultra_beast, is_event, is_costume, is_favorite, has_second_move, is_best_buddy, pokeball_type, catch_method, friendship_history, notes)

## Core Workflows

### 1. Video → CSV (Automated via GitHub Actions)

**Trigger:** Push MP4/MOV to `videos/` folder on GitHub

**Workflow steps (`.github/workflows/extract.yml`):**
1. Check out repo
2. Install Python 3.11 + dependencies: `pytesseract`, `pillow`, `ffmpeg`, `tesseract-ocr`
3. Run `pogo_extract.py --video videos/*.mp4 --out data/pokemon.csv --fps 6`
   - ffmpeg dumps frames: `ffmpeg -i input.mp4 -vf fps=6 frames_tmp/frame_%06d.png`
   - Tesseract OCR each frame (no preprocessing, full image)
   - Regex parse text output into 61-column schema
   - Write CSV to `data/pokemon.csv`
4. Commit CSV back to repo (auto-commit if changes)

**Local testing (Windows/Mac):**
```bash
pip install pytesseract pillow
# Install Tesseract exe (Windows: https://github.com/UB-Mannheim/tesseract/wiki)
# Add to PATH: C:\Program Files\Tesseract-OCR\tesseract.exe
python pogo_extract.py --video "ScreenRecording_07-29-2026 12-55-42_1-compressed.MP4" \
  --out pokemon.csv --fps 6
```

### 2. Upload CSV → Scout Dashboard

**User flow (in-app):**
1. User clicks "IMPORT CSV" in Scout Dashboard
2. File picker opens; selects `pokemon.csv` from downloads
3. CSV parsed row-by-row; each Pokémon added to roster (localStorage)
4. UI updates with new team member

**Data validation:**
- Skip blank rows
- Name lookup via `pokemon-data.js` (dex matching)
- CP → level estimation (binary search against stat product)
- IV % calculation: (atk_iv + def_iv + sta_iv) / 45 * 100
- PvP rank: simulate battles against meta (Great/Ultra/Master leagues)

### 3. Roster Display & Interaction

**Scout Dashboard features:**
- **List view:** Show all Pokémon, sortable by CP, IV%, PvP rank
- **Filters:** Type, IV range, legendary/mythical, favorited, tagged
- **Detail card:** Name, CP, moves, IVs, candy, XL candy, powerup cost, PvP rank
- **Quick actions:** Mark favorite, rename, delete, plan powerup

**Persistence:** All edits saved to localStorage immediately

## IV/PvP Calculation Details

### IV Percentage
```
iv_percent = (attack_iv + defense_iv + stamina_iv) / 45 * 100
```
Range: 0–100%

### CP Formula
```
CP = (attack + attack_iv) × (defense + defense_iv)^0.5 × (stamina + stamina_iv)^0.5 × power^2 / 10
power = 0.5 * (1.0 + level_adjusted_cpm)
```
`level_adjusted_cpm` is a lookup table; level inferred from CP via binary search.

### PvP Rank (Great/Ultra/Master League)
1. Filter meta Pokémon by league CP cap (1500/2500/no-cap)
2. For target Pokémon: simulate battle win-rate vs. meta
3. Rank by win-rate (stat product as tiebreaker)
4. Return rank %ile and absolute rank #

## Regex Parsing Rules (`pogo_extract.py`)

**Field extraction from OCR text:**

| Field | Regex Pattern | Notes |
|-------|---------------|-------|
| `pokemon_name` | `^[A-Z][A-Za-z\s]+$` (first capitalized line) | Detects swipe boundary |
| `cp` | `\bCP\s*(\d+)` | "CP 3139" |
| `hp` | `\bHP\s*(\d+)` | "HP 114" |
| `attack_iv` | `Atk\s*(\d+)` | "Atk 15" |
| `defense_iv` | `Def\s*(\d+)` | "Def 12" |
| `stamina_iv` | `Sta\s*(\d+)` | "Sta 13" |
| `type_1` | `(Normal\|Fire\|Water\|...) JAB` | First type before move name |
| `fast_move` | `JAB\|SCRATCH\|...` | Common fast move names |
| `charged_move_1` | `BOMB\|BEAM\|PUNCH\|...` (after fast move) | Charged move name |
| `current_candy` | `(\d+)\s*Candy` | "42 Candy" |
| `current_xl_candy` | `\b(\d+)\s*XL\s*Candy` | "5 XL Candy" |
| `stardust_powerup_cost` | `(\d+)\s*Stardust` | Star cost for next power-up |

**Known weaknesses (flagged for tuning):**
- `current_xl_candy` regex `\bS(1)\b` is placeholder; needs real OCR output sample to refine
- `costume` field always blank (visual-only; needs image classification, out of scope)
- `catch_method` regex assumes "CAUGHT X Y" phrasing; multi-line cases ("CAUGHT AFTER DEFEATING LEADER ARLO") untested
- `guess_name()` function detects Pokémon name by capitalization + Dex lookup; may false-positive on OCR noise (e.g., random capitals in background text)

## GitHub Workflow Details (`.github/workflows/extract.yml`)

**Trigger:**
```yaml
on:
  push:
    paths:
      - 'videos/*.mp4'
      - 'videos/*.mov'
```
Runs only when `.mp4` or `.mov` file is added/modified in `videos/` folder.

**Steps:**
1. `actions/checkout@v4` — clone repo
2. `actions/setup-python@v4` (Python 3.11)
3. Install deps:
   - `pip install pytesseract pillow`
   - `apt-get install tesseract-ocr ffmpeg` (Ubuntu runner)
4. Run script: `python pogo_extract.py --video videos/*.mp4 --out data/pokemon.csv --fps 6 --keep-frames`
5. Auto-commit: `git config` + `git add data/pokemon.csv` + `git commit -m "Extract Pokémon data from video"`
6. Push: `git push`

**Output:**
- CSV written to `data/pokemon.csv` (61 columns, no header)
- Frames stay in `frames_tmp/` (deleted after unless `--keep-frames` passed)
- Workflow log visible under repo **Actions** tab
